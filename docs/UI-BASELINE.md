## 2026-10-15 已批准的终端皮肤补充

用户确认本轮封存预览为新版基线：三种玻璃、马善政等离线字体、文字阴影、石墨等背景、白线网格和随机彩色动效。皮肤位于“我的”，本地持久化。运行加速，空闲减速或静止，后台停止动画。

任务摘要采用通栏直角背景，最后一条完全离开阅读区域的用户任务吸顶，点击原消息。输入框保留展开，Working 与时间在左上方，停止替换发送箭头。模式与模型共用弹窗，输入框短竖线分隔；未实现接口不伪造。回到最新改为右侧小矢量按钮。背景动效开启时回复透明，用户任务保留背景；关闭时兼容斑马纹。正文采用字体设置，代码等宽。

# 界面风格规范：轻玻璃、通栏终端与连续动作

> 来源：旧项目 `f8350e400cf6e7420d8283e03eb6efa37104ca79` 的 `docs/beginner-guide/15-界面风格规范.md`。保留既有规范和历史说明；其中旧版本发布/验收记录不等于本新仓库的验证结果，当前结果见 [STATUS.md](../STATUS.md)。

规范版本：1.4，2026-09-30。**这是后续界面开发的定调文件，不是重新设计提案。** 用户已经确认满意的对话视窗是基准，基线来自 0.1.0-test.62；按钮、玻璃预览和草稿功能随 0.1.0-test.65 发布，角色行与输入框紧凑间距随 0.1.0-test.68 发布。任务回看、决策及头部时间的实现规则见第 12 节，具体验收与发布状态见第 14 章。

第 14 章保存历次功能和发布记录；本章整理现在应该遵守的风格。旧章节中的历史参数与本章冲突时，新 UI 以本章为准；具体版本是否验收通过，仍看第 14 章的证据。未经用户同意，不再整体替换风格。

## 1. 一句话定调

**内容像终端一样通栏、紧凑、连续；操作像轻玻璃一样悬浮、通透、有克制的动感。**

“苹果感”在这里指材料透明、层次轻、动作连续、排版安静，不是搬用苹果商标或把 Android 改成 iOS。仍使用 Android 原生输入、返回、通知与安装能力。

五个原则必须同时成立：

1. 内容第一：不恢复左右交错的大气泡，不让工具日志占满视窗。
2. 玻璃服务操作层：标题、输入框、浮动控制可以模糊背后内容；正文与长代码不能整块模糊。
3. 运动解释状态：发送、收起、运行、加载各有来源，不能凭动画推断完成。
4. 紧凑但能点准：可见图标可以小，手指点击区不能一起缩小。
5. 不丢用户输入：切页、网络失败、延迟回执不能把尚未发送的内容清掉。

**层级**就是前后关系：正文在后，玻璃控件在前。控件下面必须留出正文避让空间；留白也属于对话背景，不是另一块蓝色工具栏。

## 3. 颜色：统一来源，不随手发明

**设计参数（design token）**就是大家共用的颜色、尺寸、字号和时间。改共用参数前，需要检查所有引用位置。

| 用途 | 浅色 | 深夜 |
| --- | --- | --- |
| 主文字 | `#20242C` | `#E6EDF3` |
| 普通次级文字 | `#6B7280` | `#9BA8BA` |
| 斑马纹上小字号辅助字 | `#525B69` | `#B6C3D4` |
| 冰川蓝强调色 | `#32608C` | `#95C8F9` |
| 雾银强调色 | `#515B6D` | `#CAD4E2` |
| 鼠尾草强调色 | `#386153` | `#A7D5C4` |
| 扫光亮芯 | `#0064D8` | `#F4FCFF` |

强调色用于模式、自己的角色标记和主要操作，不给整页涂高饱和底色。失败保留错误色，文件增删保留红／绿；不能用扫光掩盖错误。

斑马纹是相邻消息使用两种相近底色，不是每行正文画框：

| 方案 | 浅色两条 | 深夜两条 |
| --- | --- | --- |
| 雾银，默认 | `#F9FAFB` / `#EBEFF3` | `#101820` / `#1A2530` |
| 冰蓝 | `#F6FAFF` / `#E3EEF9` | `#101C2A` / `#1B2D42` |
| 青苔 | `#F6FBF8` / `#E4F0E9` | `#111F1B` / `#20332D` |
| 暖沙 | `#FFFCF7` / `#F2EADF` | `#211C16` / `#302A22` |

用户消息再叠淡角色色：浅色约 10%，深夜约 18%，增加 2dp 强调色左侧标与“你的任务”标签。双方仍同向左对齐，不恢复气泡。最后一条下面延续实际底色。加载旧历史时保持已有奇偶颜色，不让整页翻色。关闭条纹仍保留侧标和角色区分。

## 4. 字体、间距和尺寸

**dp** 是不随屏幕像素密度乱变的界面尺寸；**sp** 类似，但会考虑用户字体大小。下列是默认字号基准，不可用固定高度裁掉放大后的文字。

| 内容 | 基准 | 约束 |
| --- | --- | --- |
| 普通正文 | 系统无衬线字体，14sp | 紧凑行距，不把正文全部改成代码字体 |
| 输入文字 | 15sp，行高 21sp | 约四行后内部滚动，光标继续可见 |
| 代码 | 随包 JetBrains Mono，12sp，行高 17sp | 不联网取字体；符号不合并成连字 |
| 展开标题／副标题 | 15sp / 11sp，行高 20sp / 15sp | 各一行，长内容省略 |
| 收起标题／副标题 | 12sp / 10sp，行高 16sp / 14sp | 不挤成一段，不堆更多资料 |
| 状态／按钮辅助字 | 11–13sp | 浅色与深夜都要清楚 |
| 正文左右内边距 | 16dp | 背景通栏，字不贴屏幕 |
| 代码左右内边距 | 12dp | 不再多套缩进和边框 |
| 消息上下内边距 | 用户和回复均为 8dp | 不靠删除用户空行压缩 |
| 角色／输入框标签行 | 默认约 32dp，大字自然增长 | 不再让小字独占 48dp 高行 |
| 常规点击区 | 至少 48dp | 可见图标 14–24dp，点击大小另算 |

标题外观默认收起至少 52dp、展开至少 56dp，圆角约 24dp；收起宽度上限约 252dp。高度随字号增长，两行文字垂直居中，不用字体默认的额外上下边距挤压副标题。输入框圆角约 28dp，收起圆标约 60dp，两侧都能停靠。

「Codex / 你」标记行和输入框「消息」行采用约 32dp 紧凑布局：复制使用 Compose 的 48dp 扩展触摸区域；收起按钮则把真正的 48dp 按钮居中放进 32dp 布局槽，不能只依赖小圆形裁切控件的自动点击扩展。上下各留至少 8dp 安全空间，收起按钮左右也保留间隔，避免点击范围压到正文或邻近操作。正文标记行后间隔 8dp，不把复制按钮挤到文字上。输入编辑区上下内边距为 8dp，最小高度 44dp，四行后的内部滚动与光标跟随保持不变。单行输入框整体默认约 136dp，字号放大时自然增长；不能裁切文字来追求固定高度。

命令正文最多约 240dp 高，整组详情最多约 340dp；长输出内部滚动，标题保留收起和复制。短内容按实际行数定高度，不撑出大空白。

**标题验收要求**：.62–.73 大字号合成场景中，副标题靠近玻璃下边缘。本次改头部同时调整高度；验收必须覆盖收起／展开及 1.6 倍字号，检查文字的实际边界在玻璃内部，不能仅验证箭头居中。结果见第 14 章。

## 5. 玻璃应真的看见背后内容

**透明**是透过底色看见后面；**背景模糊**是后面的内容柔和，前景文字仍清晰。降低整段文字透明度不等于玻璃。

对话标题、输入框和浮动控制复用 `GlassMaterial`，采样真实正文背景。Android 12 及以上使用系统背景模糊，旧系统以半透明遮罩降级。禁止另造不透明白卡片替代。

清透滑块从左到右：模糊半径约从 22dp 减到 10dp；支持模糊时，顶部遮罩不透明度约从 42% 减到 12%，底部再乘 0.6。前景文字不跟着变淡。Android 8–11 现有降级使用较强遮罩，不保证滑块有同样变化。

“我的”中预览必须有**示例文字在玻璃后面**，保留一小段未覆盖内容和清晰的前景标签，用来比较变化。只能用合成示例，不能拿真实聊天、草稿做公开预览。

普通列表按钮没有可采样的浮动正文时，使用同一语言的轻半透明渐变和细描边，不宣称不存在的动态背景模糊。薄按钮不加原生投影，避免阴影透进透明底色变成灰色厚块或亮条；层次主要来自描边、选中底色和按压动作。新建弹窗保留可读面板，不为透明牺牲文字对比。

## 6. 动画：同一节奏，不是越多越好

**缓动（easing）**指动作速度如何变化：自然加减速，不突然开始／停止。主形变曲线是 `(.22, .8, .2, 1)`。

| 动作 | 基准时间 | 必须保留 |
| --- | --- | --- |
| 输入框展开／缩圆 | 460ms | 同一外形连续改变宽高和圆角 |
| 圆标左右停靠 | 420ms | 平滑移动，不挡其他控件 |
| 标题展开／收起 | 360ms | 覆盖正文，不反复挤压列表 |
| 按钮按下／回弹 | 140ms / 240ms | 轻缩至约 96.5%；禁用时无假按压 |
| 模式箭头转向 | 240ms | 与菜单开关一致，矢量不裁切 |
| 命令组展开／收起 | 380ms / 300ms | 配合淡入淡出，顺序不变 |
| 单条命令详情 | 360ms / 280ms | 收起与复制位置稳定 |
| 回到最新 | 约 320ms | 真到最后一条底部，包括避让空间 |
| 运行扫光 | 移动 1900ms＋间隔 100ms | 窄亮芯、柔边、左到右、离开边界再循环 |
| 发送成功填充 | 1200ms，短延迟 | 只播一次，不冒充运行进度 |
| 新历史补入 | 约 380ms | 淡入／轻位移，不拉回末尾 |

回复按队列依次显露，短段较慢、长段较快，单段通常 180–1800ms，并限制整批追赶时间。动画只改展示，不延迟真实状态、问题选项、批准和复制来源。重开旧对话不重播整段历史。

减少动画、系统关闭动画或 App 进入后台时，相关扫光／形变关闭，直接呈现真实状态。每个新增动画都要有静态分支。

## 7. 状态不能混淆

| 真实情况 | 应有表现 |
| --- | --- |
| 正在发送 | 旋转／扫光、防重复提交，不能清草稿 |
| 明确发送成功 | 显示刚发送原文，清除对应未变更草稿，再平滑收起 |
| 超时／结果不确定 | 保留草稿，提示核对；不自动重发或重复新建 |
| 任务运行 | 标题圆环、末尾、相关命令和运行时间共用扫光；副标题固定为当前任务摘要 |
| 等待批准／回答 | 停止假运行，保留明确的人工操作入口 |
| 已完成／失败 | 停止运行特效，失败原因不能被遮住 |
| 上滑读历史 | 不抢滚动，显示状态＋回到最新的合并控制 |
| 输入框展开且读历史 | 导航在输入框上方；收起时与圆标协调 |

扫光不是百分比，也不能证明手机通知已送达，通知需单独确认。

## 8. 草稿是输入状态，不是聊天消息

按**服务器＋账号＋对话**保存手机本地加密草稿，不上传模型／服务器，不是跨设备草稿同步。保存完整原文，包括换行、空白行、缩进。

每次输入立即更新内存并排队写入手机存储；正常返回、切页和重开 App 可恢复。清除 App 数据或卸载会丢失本机草稿，不能把它说成云备份。

- 任务和动态列表显示一行“草稿＋摘要”；只有预览合并空白、省略长内容，原文不变。
- 离开对话后，“任务 / 动态 / 我的”底部显示最近编辑的可见对话草稿，点“继续写”回原对话，不发送。
- 多段对话分别存，空草稿不显示；不在当前列表内的对话不在底部泄露摘要。
- 失败保留，明确成功才清除。比对每次编辑的唯一编号，旧回执不能删新草稿，即使文字碰巧相同。
- 创建成功但首条发送未确认时，把首条内容保留在该新对话，不诱导再次创建。
- 新版成功登录后保存账号标识，同账号重登可恢复自己的草稿；不同账号／服务器不能混用。
- 旧版现有登录没有保存账号名，直接升级时草稿暂按当前登录隔离。以后重登不猜测旧草稿归属，不自动迁移给新账号；重要未发内容先发出或复制，再退出登录。
- 加密存储初始化失败要显示警告，不能悄悄假装保存成功。草稿不写日志、不放系统锁屏通知。

## 9. 图标、可访问性与性能

返回、加号、模式和展开箭头使用矢量线条，不用 `‹`、`⌄` 等字体字符冒充关键图标。方形绘制区域居中、旋转不裁切；按钮有中文可访问性说明。

浅色与深夜各验一次。小字要读得清，状态不能只靠颜色或动画；禁用必须真的禁用，隐藏控件不能留下可点击的幽灵区域。

长列表按需创建可见行；主动展开／下载才取完整大内容。扫光在绘制阶段更新，不每帧重排整页，不为动画新增网络轮询。真实对话、账号、草稿不进入公开截图或测试资料。

## 11. 交付前检查表

- 保持通栏内容和轻玻璃，没有恢复大气泡、大执行框？
- 浅色、深夜、条纹、较大字体下有没有裁切、贴边？
- 图标真正居中，点击区够大，收起和复制仍可见？
- 动画有中间过程、方向正确、减少动画后仍可用？不能只检查状态变量。
- 玻璃后放文字，模糊与透明是否真的改变，前景仍清楚？
- 历史滚动、键盘打开、输入框收起、长命令是否挡操作或抢滚动？
- 草稿跨页面／对话可恢复，失败保留，迟到回执不删新输入？
- 复制、通知、分页、省流量与权限语义没有退步？
- 看过实际截图与错误日志？真机未确认的手感有没有明确说明？
- 本规范和发布记录是否同步，避免后续依据过期样式？

### 1.2 补充：紧凑模式、决策与任务回看

以下为本次批准的实现规范；构建和发布是否完成，以第 14 章的验收记录为准。

- 输入框 Agent / Plan 胶囊可见高度至少 36dp，内部横向 10dp、纵向 4dp，图标文字间隔 5dp；外层实际点击区域至少 48dp。大字自然增高。仅输入框使用此规格，不缩小新建对话按钮。输入框底部留白改为 10dp，单行总高度约 142dp，取代上文旧版约 136dp。
- “需要你的选择”“规划完成”和批准区域共用可读底色、明确前景色与轻描边；选中项使用低饱和强调底色和勾选状态。普通文字对比度至少 4.5:1，交互标记至少 3:1。提交时不能修改答案或重复提交，失败保留答案恢复操作，秘密答案继续遮蔽。
- 1.2 曾在标题下显示独立任务条；1.3 将它合并进头部，替换规则见下。不再保留两份入口或额外占一排。
- 阅读面板保留原文换行，提供复制和定位；面板原文采用可读底色，不牺牲对比度。新同步任务不能替换正在查看的原文或定位目标。
- 定位已有消息时关闭跟随、平滑跳转并短暂高亮约 1 秒；保留回到最新入口。缺失目标只在点击后逐页找，一次最多 3 页，每页沿用 24 条／96KiB 限制；还没找到显示继续查找。取消、失败不抢滚动、不删草稿，找不到不跳到相似文字。
- 摘要只压缩空白，不让模型总结。草稿和发送失败不替换最新任务；已接受、尚未同步入历史的回执标记同步中。旧 Gateway 只能显示已加载任务时，明确提示升级，不冒充完整最新记录。

实现主要复用 `GlassActions.kt`、`DecisionStyle.kt`、`TaskRecall.kt`、`ChatScreen.kt` 和 `TranscriptZebra.kt`；同步元数据来自 `Gateway.kt` 与服务端 `mobile-sync.ts`。

### 1.3 补充：头部任务目录与记录时间

- 头部第二行显示“共 N 轮 · 当前任务摘要”，带下划线、单行省略，点击打开任务详情。轮数按服务器确认的用户消息计数，不按可见的 24 条内容或命令数计数；草稿和失败发送不计入。已接受而尚未同步的输入显示同步中，轮数待权威同步确认。
- 摘要只压缩空白，原文保留换行；有图片显示 `[图片]`，不在目录中下载图片编码。标题圆环仍表示真实运行状态，副标题不再轮换成命令输出。收起和展开都有至少 48dp 点击区域，正文只预留头部高度，不额外预留独立任务条。
- 任务详情按新到旧列出用户消息，可逐页查看全部目录；打开只取第一页，后续“加载更早任务”才继续，每页最多 24 条／96KiB。目录不会下载命令输出，也不会替换正在阅读的原文。长原文按需获取，原文跳转继续遵守一次最多 3 页的规则。
- 每个消息／计划／命令标题有时间，收起命令组显示末项时间，展开后各命令有自己的时间。每个执行轮末尾显示用时，详情中显示完整日期、结束时间与用时。时间按手机时区格式化，列表标题用时分秒，详情用年月日与时分秒。
- 时间只来自执行端的开始时间、事件记录时间或用时字段；不使用文件修改时间、同步到达时间补齐历史。缺失显示未记录，不伪造精确时间。用时优先为记录结束减开始（包含等待），没有结束记录时可用执行端已记录的用时；有用时不代表一定有结束时刻。
- 只有确认为当前执行中的时间扫光；结束、失败、等待用户或减少动画时静态。运行秒数只在 App 前台本地更新，不发起计时网络请求。完成后不继续累加，不把旧历史全部做扫光。
- 已展开的完整消息不会因时间／末尾标记变化退回成短预览；正文版本与状态版本分开比对。任务计数、时间和目录为可选扩展，旧 App 忽略；旧 Gateway 无法给出轮数时明确提示升级。

### 1.4 补充：保留现用 .82 的任务阅读面板

本节同步已发布版本的规范，避免隔离开发基线倒退；不是新增设计提案。

- 任务详情是近全屏阅读面板，不是默认提示框：左右外边距 10dp，最大宽 640dp，约 94% 可用高度，避让系统安全区域。
- 顶部标题和关闭按钮、底部定位操作分别固定，中间正文独立滚动，不遮挡最后一行。正文左右内边距 16dp，14sp／21sp 行高；摘要最多两行。
- 最新任务在顶部原位展开，原文只显示一次。选择旧任务在原位置展开，不把旧任务移动到最上方。展开高度约 240ms 连续变化，减少动画直接切换。
- 发送时间在每项右上角，结束时间在右下角，用时另列；跨天保留日期。对话框继承系统字体比例，较大字号允许换行增高。浅色、深夜、1.6 倍字体和长文滚动都需验收。
- 不改变原文获取、分页、复制、准确定位及冻结当前阅读原文的规则，不增加全量历史下载。

多电脑入口、终端选择和任务筛选先沿用既有列表、胶囊、底部轻提示与状态文字，不另起视觉风格。本文只定 UI 语言，**不代表多电脑控制已开发**。

整体风格改变必须先展示差异并取得用户同意，再更新规范版本。普通功能不能以“优化”为由悄悄重新定调。
