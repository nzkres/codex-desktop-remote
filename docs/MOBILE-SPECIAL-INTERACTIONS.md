# 手机特殊交互清单与第一批修复范围

核对时间：2026-10-14。依据当前源码72b7b29、已固定Desktop 26.1007.2314.0本地安装包的只读检查及合成接口复现。现用Windows为alpha.13；alpha.14仅本地签名，Android alpha.7受控构建通过但上传受额度阻止。本次没有升级手机、连接器或服务器。

## 为什么看得到回复却没有选择框

手机看到的是经过连接器整理的对话内容，不是Desktop窗口的镜像。问题不是屏幕太小，而是结构化交互数据及回传动作没有打通。

- 普通等待问答：`src/service.js:122`一旦发现原生requests就抛desktop_action_required；139–141固定返回空pendingQuestions/pendingApprovals。手机因此拿不到卡片，甚至会整段读历史失败。
- 本次异步选择框：固定Desktop代码把这类问题保存在agentMessage.questions，通过原条目ID和问题序号定位；已接受的回答另有结构化关联。`src/vendor/mobile-sync.js:13`只保留文字等白名单字段，没有questions，选项随投影丢失。这不是简单把pendingQuestions从空数组改掉就能全部修复。
- 回答链路：Android已有QuestionCard及Gateway.answer，但连接器HTTP不接受questions/answer、approvals/decision、mode或implement-plan；Follower只允许开始回合、停止回合、加载历史。
- 普通文字不是原生答题：现有send要求空闲，待问题/活动回合返回thread_busy。不能让用户手打“同意”或原生内部标记来伪装一次正式提交。

相关入口：`src/service.js:119–141,287–305`；`src/follower.js:204–217`；`src/vendor/mobile-sync.js:13–23`；`android-native/app/src/main/java/dev/codex/remote/Gateway.kt:274–280,334–340`；`ChatScreen.kt:687–729`。行号以本次审查为准。

## 每种操作怎样在手机呈现

| 类型 | 当前Desktop连接器能力 | 手机应该显示/怎样操作 | 优先级 |
| --- | --- | --- | --- |
| 普通单选、文字回答 | UI存在，数据和提交未接通 | “需要你回答”；逐题选择或填其他答案，再点提交；推荐项只提示、不替用户提交 | P0 |
| 异步选择/确认（本次遇到） | 消息questions投影丢失；活动回合答复通道未接通 | 跟在对应提问后；不隐藏正在更新的回复；核对原题后提交，明确回答是否已接受 | P0 |
| 一次多道题 | UI能逐题，后端不支持提交 | 显示“第几题/共几题”，答齐后一次提交；保留选项说明 | P0 |
| 单题多选/选项选择器 | 现有Map<String,String>仅单答案；不同原生请求类型 | 仅原生明确支持多选才用复选框；不能把多个选择拼成字符串代替协议 | 后续，先显示需电脑处理 |
| 命令执行/文件修改审批 | 卡片存在，后端未接通 | 查看完整命令、目录或diff，再选择“仅批准这次/拒绝”；默认不批准，不扩成永久授权 | P1独立接入 |
| 扩大目录/网络权限 | 手机没有完整授权模型 | 明确显示申请范围与“需在电脑处理”；不简化成笼统同意 | 暂保留Desktop |
| MCP表单、登录、身份验证 | 当前未适配；原生有独立elicitation及验证流程 | 显示“需要在电脑完成登录/验证”，保留正文；不把密码/验证码当普通聊天回答上传 | 暂保留Desktop |
| Plan完成后实施 | 有“继续规划/实施计划”UI，实施接口缺失 | 继续规划可输入新要求；实施按钮只在原任务新鲜计划可验证时启用，展示会开始执行 | P1 |
| Agent/Plan切换 | UI存在，mode接口缺失 | 展示当前模式；不支持时禁用并说明在电脑切换，不静默切换或假成功 | P1 |
| 停止当前执行 | 已有原生stop链路和回合校验 | 点击停止→核对中→已停止；超时显示结果待核对，不连点重发 | 保留并补特殊状态说明 |
| 新建任务 | Android有入口，当前Desktop服务未实现 | 暂提示在电脑新建；新标题同步后手机接续，不能复制另一份任务作为替代 | 后续 |
| 工具输出、文件差异 | 已有文字预览/详情获取 | 展开输出或diff；文件路径不是手机本地文件，不提供误导的“打开本机路径” | 保留 |
| 图片、附件、链接/产物 | 图片仅计数/占位；附件发送未实现；链接可点击性未证明 | 区分已能预览、需下载、只能电脑查看；本地文件需专门授权下载接口，不能无条件暴露任意路径 | 后续 |
| 队列、运行中插话、子代理跳转 | 现有Follower无这些动作；子代理部分记录不在手机可见类型中 | 明确能力限制，不能把普通发送伪装成插话、排队或子任务控制 | 后续 |

“按钮已经有”不等于“当前连接器支持”，也不等于“手机实机已验收”。上述部分UI来自旧项目复用。

## 第一批只补最常用的问答闭环

1. 分别解析普通requestUserInput与agentMessage.questions，不混用请求ID；只信已验证原任务新鲜状态中的问题。
2. 同步正文和问题卡片；待提问不再把整个正文读成错误页。未知审批继续阻止执行，但在手机明确显示需电脑处理。
3. 新鲜核对任务/回合/问题及题目版本之后提交；普通问答使用原生submit-user-input候选协议，异步回答需独立核实原生已接受消息/插话路径，不能直接放宽send的assertIdle。
4. 选项说明保留；“其他答案”始终可辨，不能用特殊答案字符串充当状态标识。多题、草稿、切换电脑隔离，屏幕旋转/刷新不丢已填答案；秘密输入先留Desktop处理。
5. 提交前无默认授权；提交中禁用重复动作。成功以Desktop回执与问题状态为准；网络超时显示“提交结果待核对”，先刷新核对，不自动重交。
6. 电脑先回答、原问题变化/撤回、过期或当前任务变化时手机卡片转为已处理/失效，保留可理解的状态，不把旧答案交给新问题。
7. 未支持动作显示原因/处理位置，不能保留看似可用却只能501的按钮。读取与执行能力分别声明，服务器不支持不能从已连接状态猜测支持。

本轮完成的是定位、合成复现、交互清单和可点击演示；产品协议扩展及APK/连接器修复尚未完成。不得以演示中的“提交成功”当作真实手机功能已经可用。

## 可重复的真实代码复现

运行 `node scripts/demo_mobile_special_actions.mjs`。此脚本只使用合成任务/问题、临时目录、内存令牌及随机回环端口；断言异步问题字段被丢弃、待问题阻断读取及普通发送、问答/审批/模式/实施四条路由501，验证Desktop调用次数始终0。它展示现有缺口，不执行任何真实问题回答或审批。

后续修复必须反转相关产品回归预期，覆盖单选/自由输入/多题、不同电脑相同requestId、问题变更、Desktop先回答、网络超时、重复点击、重启后未知提交以及浅深色/大字/键盘/读旧历史不被抢滚动；最后由用户在专用任务分别验收手机回答→Desktop继续、Desktop先答→手机更新。
