# 已有验收空对话接入手机

2026-10-16，用户要求把已有“手机新增对话 · 空对话验收”接入手机列表并核验打开，保留同一对话和全部原回执，不重新创建。

## 原因与处理

现装 Windows alpha.22 在线，真实手机 HTTPS 路由返回 65 条对话、create=true。该对话由独立创建探针落盘，来源为 `desktop_remote_create_probe`，没有手机创建回执，因而被正常目录过滤。原 SQLite title 为空；不能把测试记录伪装成手机创建，也不修改 Desktop 内部资料来绕过过滤。

Windows alpha.23 支持本机维护配置 `linkedConversations`，每项完整包含 threadId、projectPath、title、originator、threadSource、allowEmptyHistory。必须按精确已有 ID、目录、来源和线程类型与只读实时 SQLite 元数据匹配，来源仍限 vscode，guardian/subagent 仍排除。仅匹配记录能在手机使用维护者指定的备用标题，Desktop 原标题和历史不变。接入不写任何手机创建或发送回执；没有开放远程接入接口。

明确接入的空历史仍需原生 Desktop owner、目录、当前权限、完整历史快照和明确 idle。其他空历史不因此自动放行；运行中、权限未知、未确认发送/停止继续使用原门禁。原生 Desktop 继续拥有执行，接入不启动 app-server 或模型回合。

## 验证层级

- Node 回归 198 项通过，包含来源绑定标记与本机接入记录同时存在、撤销接入、空历史权限/运行状态、无伪造创建回执。
- Python 完整回归 223 项，其中 216 通过、7 按环境跳过；针对性测试覆盖精确 ID、目录、来源、类型与无数据库写入。
- 本机原生同一 ID 接管/权限/目录通过，idle、零回合、0 模型输入；原 33 条回执及历史文件摘要未变。签名构件、实际安装、手机 HTTPS 列表与 open=1 路由分别记录，不能相互替代。
- 当前没有可连接的 USB 手机；即使真实 HTTPS 打开通过，也只能证明手机使用的服务链路，不能声称看到了手机屏幕。

本版只更新 Windows；手机 alpha.21 与服务器中继程序不变。安装继续使用原签名更新事务，保留身份、连接设置、全部原回执与未知结果保护。
