# 手机新建对话：缺口与接入要求

## 2026-10-16 本轮实现与验收边界

用户已明确允许短生命周期 app-server 仅创建空对话的方案，并要求保留现有连接和发送回执；随后确认当前无法 USB 连接手机，先完成构建与测试。

已接入：正式对话首页“新对话”胶囊、对应电脑的去重项目清单、可选标题与消息草稿、加密持久创建编号、超时后的“核对并继续”、原生空历史读取。创建后消息保持草稿，由用户点击原发送按钮，不自动发送，不更改原发送回执协议。未确认请求不能编辑成另一项目/正文或换编号重建。

Windows alpha.22 仅对 all-local 与固定 Desktop 26.1007.9446.0 开放。创建链路调用 initialize → thread/start → thread/name/set → thread/read，然后关闭辅助进程；原生 Desktop 接管同一 ID 并通过目录与权限检查后才返回成功。命名用于落盘，实验发现未命名的零回合对话退出后无法读回。已有回执中的创建 ID 才能通过目录过滤被本机连接器再次发现。

真实电脑验证：独立空资料目录重启读回通过；另创建唯一一条“手机新增对话 · 空对话验收”，辅助进程退出后原生 Desktop owner 接管成功，cwdMatches=true、permissionsVerified=true、turnCount=0、status=idle、modelInputs=0。真实身份、发送回执和当前连接器未被更换，也没有发测试消息。

代码/测试/构建证据更新见 STATUS.md。本机验证不等于手机安装或真实手机点击新建；本轮未更换私有 OTA 索引。以下记录保留为原缺口背景，文中旧版本的“不支持”不代表本轮候选已安装。

2026-10-16用户指出正式手机缺少新对话。核查结论：功能尚未接通，不在Android alpha.20或Windows alpha.20的交付范围内。本记录不代表实现完成，不能据此启用创建按钮或发布可用声明。

## 现有缺口

- 正式`ConversationHub.kt`只有设备与筛选，没有新对话入口；`MainActivity.kt`旧`SessionList`按钮固定禁用。
- `NewTaskDialog`及`Gateway.create`保留旧原型代码，POST `/api/projects/{id}/sessions`，但`src/service.js`不实现该路由，快照`capabilities.create=false`。
- 现有IPC是原生已存在对话的follower协议：读、发送、停止、问答，不包含创建。不得新增猜测的方法版本或把另一任务当新任务。
- 已只读检查固定Desktop 26.1007.9446.0安装源码。其`codex://threads/new`和`codex://new`深链最终导航到首页并设置`prefillPrompt`，不创建、不提交，不能当手机创建成功。
- Desktop另有原生工具创建能力，但走独立工具桥及调用上下文核验。尚未建立手机请求作为独立调用方的合法接入；不能借用当前模型回合或伪造工具调用来绕过它。

## 用户操作与界面

沿用现有玻璃风格与紧凑首页，在筛选行右侧增加“＋ 新对话”，不另加一排常驻标题。选择电脑后只使用该电脑返回的项目目录；弹窗显示电脑、项目、可选标题和首条消息。模式和模型只在连接器明确支持时选择，默认继承Desktop，不提供假切换。

新对话确认后进入原生返回的真实对话。首条发送未确认时保留原文及消息编号，禁止重复创建；设备切换、断网、取消和迟到响应不得把内容转交其他电脑。

## 实现前的必要条件

1. 核实可用于已授权手机请求的Desktop原生创建入口、版本与调用方身份，不新增独立执行器或修改Desktop内部文件。
2. 新建项目清单必须由对应电脑核验、去重；手机提交项目标识，不能任意传路径扩权。
3. POST使用稳定createRequestId及内容摘要；在副作用前持久化创建账本。仅原生明确返回并读回正确项目/对话ID后记成功；未知结果保留记录，不换编号重试。
4. 创建与首条发送使用两阶段回执；超时分别呈现“创建待核对”或“已创建，消息待核对”，不得返回空白失败后诱导重建。
5. 连接器明确宣告create能力与原因；旧版/离线/未核验目标不可执行。身份、原发送回执及更新保护继续保留。

## 验收

合成验证需覆盖重复点击、创建成功但响应丢失、重启、首条发送超时、跨电脑迟到回执、无效项目与权限变化。真实验收需手机创建、Desktop同一个原生新对话出现、首条仅提交一次、手机继续读取及接续。当前未进行真实创建，没有新的APK或Windows版本发布；现有连接保持。
