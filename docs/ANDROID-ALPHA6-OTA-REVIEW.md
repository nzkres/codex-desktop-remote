# Android alpha.5→alpha.6 OTA 候选与验收

当前实机基线是 Android alpha.5、Windows alpha.7、relay alpha.5：手机已安装、登录、配对，并与 Desktop 在同一任务完成文字接续。alpha.6 的产品目标仅是未选择电脑时停止任务和动态请求、沿用原界面提示先选电脑；已选电脑、账号、草稿和真实 401/404 错误必须保留。Android alpha.6 的 CI、受控签名、发布及手机 OTA 结果分别以 [STATUS](../STATUS.md) 为准，不从版本说明或下载结果推断完成。

## 候选进入私有 test 源前

1. 对无选定电脑、选定电脑、登录失效及真实任务不存在分别回归：无目标不发任务/动态请求或旧通道后台轮询；选定后原路径工作；401/404 不被选择引导遮盖；账号、选定电脑和草稿不被清理。保持现有发送、审批、未知回执及 OTA 活跃门禁。
2. 先跑 Android JVM/UI 与普通 CI debug 验证并审查 PR；普通 CI debug 的空 trust 和临时证书**不能**覆盖现有受控 alpha.5。必要审查完成、PR 合入 main 后，才使用原受控证书在既有 main 限定工作流构建 alpha.6 候选；本清单不代表该构建已执行。
3. 对实际候选独立核对包名 `dev.codex.desktopremote.lite`、`versionCode` 6、渠道 trust、公钥、受控证书与手机已装 alpha.5 的证书连续性，并记录 APK 大小/SHA-256、源码、CI 与签名证据。不能用同一下载页的哈希表代替信任根；不卸载现有 App 绕过签名或数据问题。
4. 只用固定 `https://106.53.126.69:9443/desktop-remote-updates/test/android/` 私有源。版本化 APK 与签名元数据分别核对包名、渠道、版本、序号、有效期、大小及哈希；源文件落地并验证后再更新 `latest.json`。保留旧包与发布记录，同版不换包；过期元数据重新受控签发，不关闭验证。匿名和失效账号应拒绝，不能把登录令牌发往另一 origin。

## 现有手机在线验收

1. 更新前记录手机实际 alpha.5、证书、账号、选定电脑、专用任务与一条非敏感草稿；核对当前 Windows alpha.7 和 relay alpha.5。使用已登录、已选且已连接的测试电脑，不重新配对或迁移身份。
2. 在“我的 → 版本与更新说明”检查并下载候选，核对说明与下载进度。安装前重新取得所选电脑的空闲、权限和回执确认证据；正在发送、待审批、活动或未知操作、证据缺失时应延期。下载期间状态变化须重查，不能沿用旧证明。
3. 由 Android 系统确认覆盖安装。取消或返回原 App 只能记待安装/可重试，不能算成功；不以下载完成、安装对话框出现或 App 能打开代替版本验证。
4. 重开后核对实际 `versionCode` 6、自身 APK 哈希、更新 ledger 与待安装回执；再取新鲜任务证据。确认账号、选定电脑、草稿、原任务历史保留，未选电脑引导和已选电脑读取均正常。用同一专用任务完成手机→Desktop→手机文字接续，并分别记录真实网络、下载、安装、回执、任务与数据保全结果。

发生证书冲突、登录变化、未知安装结果或任务状态不明时保留应用与数据，记录脱敏错误并停止后续尝试；不要重复发送未知结果的任务消息。Android 不支持把 alpha.6 直接降回 alpha.5 作为普通 OTA 回退；修复需另行审查更高版本。通用协议与失败边界见 [OTA](OTA.md)、[验收计划](OTA-ACCEPTANCE.md)和[Android 安装指南](install/ANDROID.md)。
